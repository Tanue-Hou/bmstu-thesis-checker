# 多页PDF与博士副本修复（0.2.4，build 230）

证据：evidence/multipage-phd-repair。comparison.json记录19个修复前输入的逐规则原程序配对；repair-comparison.json记录第20个原程序输入，即实际修复副本。所有输入均有哈希、原程序截图和文本，另保存PDF逐页提取结果、静态函数来源和完整修改日志。

## 多页PDF

博士模式已验证1–3页、无旋转、嵌入Times New Roman+ToUnicode、每页至多一张PNG图表的有限格式谓词。第2页表格7磅、超大图像，以及第3页非黑文字、非A4纸张均被原程序检出；本地结果提供对应页码。超出配置仍检查本地属性，但保留pending状态。

PDF的18.5/19/24/36/72磅探针均含超过10个大字号字符，原程序均未输出大字号警告。恢复的PDF文字函数00477f50引用下限设置006ee118，没有引用DOCX上限006ee11c。仅能说明所测路径没有沿用18磅异常上限，不能断言所有PDF均无上限。学校要求的正文14磅等必须作为独立模板策略，不冒充原程序规则。

## PDF结构差异

13/14页完整文本对照确认博士摘要标题与ОГЛАВЛЕНИЕ目录标题缺失的两个谓词。对PDF提取的NBSP先做空白规范化，避免完整参考文献标题误报；结构标题按独立文字行识别，正文提及或目录条目不充当正文标题。仅这两个缺失谓词提高验证状态，其他缺失元素保持人工复核。

完整结构基准仍被原程序指出文字落入页边、上边距和页码位置问题。当前本地引擎没有覆盖这些几何检查，也未复制目录页码解析、正文与目录对应关系、封面和参考文献完整性。native_comparison_limits和Markdown报告必须保留此提示；零条本地诊断不代表原程序通过。14页文本结构样本不能扩大多页图表格式证明到任意页数。

## 博士副本修复

MCP preview_thesis_fixes / fix_thesis_copy以及CLI现在允许work_type=phd，限一个纵向节。仅开放page_size_a4、font_size_anomalies、text_color_black三个动作。先预览，再在用户授权范围内创建新副本；用户已要求副本修复时无需再问同样的确认。

- 正文字号目标必须来自用户或已知Normal样式，不能把8磅异常下限当推荐字号。
- 表格、图像、超链接、公式、域、内容控件、文本框、修订内容、页眉页脚保持原样，未修项目写入跳过记录。
- 不自动修博士边距、行距、缩进、结构或PDF；多节与横向博士文档拒绝自动修复。
- 博士修复必须同时校验该格式/类型的规则证据以及原程序修复前后证据哈希。
- 实测组合DOCX原程序4条诊断，执行5项属性修改后原程序无意见；原文件未变，文字/表格/图表/边距及其他ZIP成员保持一致，日志可逆转全部XML修改。这是合成样本的验收，不是任意论文通过承诺。
