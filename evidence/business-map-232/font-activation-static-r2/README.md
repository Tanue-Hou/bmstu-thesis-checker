# 表格/文本框边界对字号启用列表的静态索引（232）

本索引将现有原生边界 trace 与同一 SHA-256 的 x86 反编译/指令证据对应起来。没有执行目标程序。

## 关键落点

可复核的空记录插入指令在 `00437374` 尾部：`00437d12` 将静态地址 `006ceff0` 交给字符串构造函数，`00437d32` 调用 `parser+0x558` 对象 vtable `+0x38`，传入构造后的字符串。边界 trace 报告相应记录长度为 0。故可把这个虚调用作为断点，观察调用者和返回地址来判定具体结构路径。

同一函数用 `parser+0x558` 的 vtable `+0x14` 查询列表长度。启用检查在 `00437aba` 查询长度、`00437abd` 比较 `0x3c`，`00437ac0` 对 `<=60` 跳过置位；因此该分支在长度严格大于 60 时置 `parser+0x11d` 与 `+0x11e`。该判断发生在尾部 `+0x38` 插入之前，正好允许结构结束时的额外空记录影响随后运行片段的 enabled 状态。

## 结构调用链

表格路径较明确：`0041c6ac` 的 `w:tbl` 分支在 `0041caa9` 调用表处理器 `0041614c`；该函数在 `00416314` 调用行处理器 `00415824`；行处理器在 `00415f30` 调用 `00437374`。行处理器伪码从 `recovered_pseudocode.c:9641` 开始读取 `w:trPr`，并在 `9823–9827` 结束时调用段落/文本后处理。于是表格行结束可以沿这条共享后处理路径追加记录。

文本框路径为 `0041dee0` 在 `0041e135` 进入 `0041c6ac` 解析 `txbxContent`；`0041c6ac` 再于 `0041c9c1`/`0041ca35` 调用 `004078c0`/`00408a08`。两者都有到 `00437374` 的调用。`004078c0` 的候选 callsite 为 `00407947`、`004082e3`；`00408a08` 的候选 callsite 为 `00408a77`、`00408c70`、`00408deb`。静态调用链表明内层内容会复用传入的解析器对象，但不能单凭静态文本确定边界 trace 中具体哪一个 callsite 对应最后的空 host 记录；在 `00437d32` 断下并记录返回地址即可区别这些分支。

## 证据边界

边界 trace 的顺序是动态证据；这里的静态证据定位产生它的共享 append 点和结构入口，不把 XML 段落序号等同于原生列表长度。`+0x38` 在调用点表现为单参数 append，`+0x14` 的返回值被作为长度作零值/阈值比较；其他虚方法槽位（如 `+0x18`、`+0x24`）的高层语义不在本索引中命名。`DAT_006ceff0` 的零长度特征引用现有 trace 观察，不外推到其他构建。
