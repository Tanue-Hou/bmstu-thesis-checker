# 业务地图与后台入口调查：阶段证据

此目录是研究证据，当前稳定 CLI / Skill / MCP 仍为 v0.2.8；这里没有新增论文修复权限，也没有证明原程序可无界面检查论文。

- `function-index-r2/`：修正符号地址识别后的静态导航索引。收录 10,192 个函数，只有两条已解码诊断完成直接静态关联；函数数量不是业务覆盖率。
- `diagnostic-map-r2/`：扩大字符串扫描后的候选地图。32 条诊断关键词候选中有 8 条出现静态引用，涉及 4 个函数；其中包括词库加载、工作名称、封面加载和下载错误，不能都计入论文规则。修正嵌套区间匹配与 UTF-16 偶数字节对齐；r1 保留。
- `resource-codepage-r1/`：新发现的强交叉证据。原资源 `RU_PREFS` 解压首行按 CP936 解码，精确复现进入业务函数前捕获的错误参数和后续索引；按 CP1251 解码对应有效索引 15。仍待捕获具体转换 API，以及验证可用的本机解决方式。
- `pe-resources-REA.json`：完整 REA 资源清单，Evidence ID `ev_916f0183d8507c430bbbf49f7955dffead192748e34de0462665b6db91fa2734`；77 个资源。资源目录 code_page 字段是 1252，并不能据此宣称实际词库是西欧编码；这里以实际载荷字节和运行参数对照为准。
- `startup-analysis-r1/`：两次实际启动异常、指令和代码页候选解释，可由 `analyse_native_startup.py` 重算。不是仅凭界面提示推断。
- `startup-fault-r2/`、`startup-fault-r3/`：独立进程运行记录；相同位置因字符派生索引异常而访问无效指针，原文件未变。
- `startup-russian-r1/` 至 `startup-russian-r7/`：俄语加载器与调试器联合实验。首轮清理异常导致未生成 JSON；后续保留失败或受限记录。r5 记录加载器返回 3221225781（0xC0000135）；将探针放到加载器目录后，r6/r7 已观察到目标子进程，但在时限内仍未进入业务断点，不能列为俄语验证通过。所有实验只针对本次创建的进程。
- `antigravity-review/`：Gemini 3.8 的独立静态意见，非执行证据。其中“thiscall”属于不充分推断，实际 EAX/EDX 参数指令不支持该 ABI 标签；不采纳。四个命令行读取函数之外还有一个同名导入跳板，分析 JSON 同时列出，不能误认为第五个业务消费者。
- `antigravity-fault-review/`：用户明确授权发送少量技术片段后调用超时，没有可用复核结论。
- `startup-russian-suspended-r1/` 至 `r3/`：仅匹配本次加载器的直属目标，核对完整路径与程序哈希后附加。首次观察到挂起计数 2，单次恢复后的两个实验均先在系统加载层出现异常，没有业务断点命中。r2 的 WOW64 寄存器并不是 64 位异常地址的实际上下文，不能用其 `preferred_va` / `instruction_bytes` 解释系统异常；r3 已明确标记这项架构限制。延迟 1 秒也未解决。未据此修改原程序或判定其俄语路径逻辑。

本地协作的 Luna 完成索引修订与 Locale Emulator 的只读 IL 检查；后者证据在相邻 `locale-loader-il-20261015/`。Antigravity 只收到所列技术片段，没有发送论文。

下一步：解决俄语加载器与调试器初始化配合；捕获原始字节到 Unicode 的转换；随后才追踪工作名称、计数与阈值分支，并将同输入正反边界例通过的判据纳入 CLI。实验脚本不作为面向论文用户的入口。
