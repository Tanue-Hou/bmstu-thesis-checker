# Native section 计数静态映射

原生入口链为 `FUN_0047a528 → FUN_0043dd1c → FUN_0043c408 → FUN_0040b31c`。最后一跳的 PE 调用指令位于 `0x0043ccc6`，对应主文档解析中的 `w:sectPr` 分支。恢复的 calls.tsv 只列出 `FUN_0043c408` 为 producer 的直接调用者；表格、OMML、图片和图表路径没有被列为直接调用者。

`FUN_0040c770` 选择当前 section 记录，页眉和页脚距离分别写到记录 `+0x28` 与 `+0x2c`。两处不匹配计数都由 `FUN_0040b31c` 写入 parser `+0x28c`。同一解析分支还读取 header/footer reference 的类型和关系 ID，但静态证据没有显示它在这里读取这些故事正文。

主报告门位于 `0x0047e293`，比较 `[ECX+0x134]` 与零；前一条指令从 `[EBP-0x5dc]` 取出 ECX。DOCX 路径把 parser `+0x158` 存入该栈槽。报告槽 `0x4d` 的偏移为 `0x134`，所以 `(parser+0x158)+0x134 = parser+0x28c`。这证明静态地址别名。要动态确认，应在报告门命中时同时核对栈槽解引用值、ECX、parser 基址和两处计数值；本目录没有该门的动态命中记录。

因此，单显式 section 的距离计数谓词不自动覆盖多 section、独立故事正文或嵌套表格/OMML/图片/图表。它们是否通过共享状态影响最终计数仍需对应入口与运行时关联证据。
