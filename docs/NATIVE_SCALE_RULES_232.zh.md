# 原生232字符缩放

52次原程序执行（硕士26、博士NKR26）覆盖26个不同合成输入。每次保留run属性/启用状态、实际累计分支、三个最终计数槽、报告发出分支与完整提示原文；CLI按同输入哈希核对。它们不代表真实论文准确率。

| 分类 | 实际条件 | 计数与报告 |
|---|---|---|

| 极小观察槽 | 启用且整数缩放2..30% | parser+19c → 主槽11，本组未发普通小缩放提示 |

69/70%、130/131%、10/11字符均做两种模式对照。空格11个计11，6个表情计12。文本框内首run的大缩放即计入，不受大字号“此前已处理字符>100”门限制。正文检查启用时序与字号相同：分类先于段落后处理；精确引言标题后启用，无标题时第61段结束才影响下一段。

普通段落、单格表格、简单文本框和直接/basedOn/关联字符样式已对照。关联样式131%可覆盖段落69%，直接100%覆盖后不计异常；标准OOXML缩放值与原程序兼容值分开保留。每个命中位置返回原始XML/run路径、实际缩放、UTF16数量、启用序号和属性来源。
