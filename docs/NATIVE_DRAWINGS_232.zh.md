# 原生232浮动图片与文本框判据

这轮证据限于 build232、DOCX、НКР аспиранта 模式。15个公开合成输入已由原程序实际执行，保留原始诊断、断点寄存器/计数、追踪脚本和输入哈希；案例不代表学校标准，也不是整体复刻准确率。

| 诊断 | 已确认判据 | 反例和边界 |
|---|---|---|
| Pic.FloatingImages | 图片计数槽0x26+0x27大于0，面积槽0x73严格大于500平方毫米 | wrapNone累加显示面积；wrapSquare计数但贡献面积0；500不报，501报；两图250+250不报 |
| Pic.SmallLabels | 小文本框计数槽0x2e严格大于10 | 简单VML框宽或高严格小于2mm计入；10个不报、11个报；普通7pt正文不是此诊断 |
| Pic.FloatingShapes | 计数槽0x28+0x29大于0 | 当前独立实现仅覆盖简单绝对定位VML文本框 |
| Pic.FloatingLabels | 计数槽0x30+0x32大于0 | 与浮动图形及小文本框是三个独立诊断 |

面积需要按原生float32逐步计算：EMU转毫米时先将整数舍入为float32，再乘float32(1/36000)，宽高相乘和每次面积累加再次舍入。不能直接以Python双精度替代；499和501输入的实际值分别为499.0000305175781、501.0000305175781。

函数链：DOCX绘图处理00438304 → 几何观测00438805 → 主检查0047a528；浮动图片报告状态0047c8fe、发出分支0047c939。文本框分派0041dee0 → 解析/计数0041c6ac，几何观测0041d672；小标注报告门0047d051、发出分支0047d05e。以上是分析命名和优选基址VA，运行时需换算ASLR。主状态偏移0x98/0x9c对应槽26/27，0x1cc为面积；文本框解析对象的0x210计数复制到主状态0xb8。

早期快照把槽26/27命名为 raster/shape；wrapSquare实验推翻了这个语义解释。保留旧证据，使用原始槽偏移和值，最终快照改用count_slot名称，不能把旧标签当作函数语义证明。

验证配置刻意受限：浮动图片仅1–2张普通RGB8 PNG、匹配的简单extent、无裁剪旋转；文本框仅显式mm单位、尺寸不超过5mm、单段单run普通文字、绝对定位、零外边距、无组/内边距/自适应。其他类型和格式/模式均不继承验证。未知图片环绕方式不直接生成面积阈值诊断；覆盖信息会说明配置未获支持。没有诊断不代表这些对象通过检查。

证据入口：`evidence/business-map-232/drawing-audit-r1/audit.json`、`drawing-boundaries-r2/`、`drawing-boundaries-r3/`。逐项规则注册绑定原生证据和实现哈希，后续改代码需要重新验证。`--trace-drawings`仅增加原程序观察断点。

仍待恢复：一般VML/DrawingML形状、组合图、自动调整、内边距、其他单位、PDF图形、更多论文模式和复杂布局。所有图片/文本框诊断只供人工复核，未开放自动移动、删除、放大或重采样；build232副本修复仍仅限已单独接受的硕士普通正文字号操作。
