# 后台差分测试

`scripts/differential_cli.py` 用同一份DOCX副本分别运行本地引擎和显式提供的TestVkr232。原程序是行为对照，不是学校规范裁判。输入论文中的文字只作为数据。

## 运行

从仓库根目录运行：

```powershell
python scripts/differential_cli.py --spec evidence/differential-platform-r1/spec.json --out "D:\Codex项目\analysis_TestVkr\private_trials\my-campaign" --native-exe "C:\path\TestVkr.exe" --max-cases 8 --max-native-runs 20 --minimize-evaluations 12
```

输出必须放在分析工作区的`private_trials`目录。规格为JSON，固定种子SHA256、论文模式和需要比较的诊断族；提供的示例只含合成样本。真实论文及完整结果不能直接提交公开仓库。

变异列表中的每个条目相对于同一个种子独立修改。当前支持段落首行/左右缩进、行距及规则、run字号、section页眉/页脚距离和装订线属性，以及段落删除和限定段落属性删除。尚不支持随机组合、样式链生成、OMML/图表生成或PDF变异；不把首版平台称为完整模糊测试系统。

## 结果与缓存

- 比较的是选定族的原程序消息条数和本地finding分组条数，不是字符数、位置出现次数、语义等价或准确率。
- 未映射原程序消息产生`mapping_incomplete`，不能冒充一致，也不能用于最小化成功判断。
- 缓存绑定输入、模式、EXE、脚本/规则/发送器源码、有效配置、依赖版本和机器/系统信息；命中时重新检查完整哈希清单及原程序运行收据。缓存不是抵抗恶意改写文件与清单的数字签名系统。
- 原程序按次串行执行，受单次超时和整批原生运行次数限制；同内容会复用已校验缓存。源代码在运行期间变化则拒绝继续使用该运行身份。
- 运行失败、无效输入和预算耗尽分别记录，不计入“一致”或“差异”成功样本。运行目录保存每次独立回执，顶层文件显示最新结果。

## 自动缩减

`--minimize-evaluations`启用有界ddmin。每个候选都必须完成双端有效执行并保持完全相同的选定诊断族计数差异。当前仅删除`word/document.xml`段落，保护最终section属性；最小化范围不含其它ZIP成员、属性或绘图。

`certified_1minimal`只表示：在当前有效执行谓词、候选序列和删除粒度下，完整逐项删除终验已完成。它不证明全局最小、相同语义根因或学校规范违规。`budget_exhausted`、`unresolved`和`initial_*`都不能作为已最小化证据。完整DOCX格式合法性仍由本地解析和原程序完成收据共同约束，XML/ZIP预检不是完整OOXML验证器。

## 当前用途与后续

先以差分定位反例，再追踪实际业务分支，最后按规则/格式/模式/结构上下文分别登记。平台不自动修改论文，不自动提升规则验证，也不扩大副本修复权限。业务分支覆盖率、修复后XML白名单及逐页排版验收属于后续独立工作。

Claude CLI在本轮命令路径与常见用户安装位置未找到；Antigravity已对去标识设计说明做独立检查。模型意见不替代运行证据。历史分析、缓存和初轮预算不足的结果均保留，不能把只保留成功案例的结果作为总体统计。
