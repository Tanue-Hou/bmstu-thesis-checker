# 232 DOCX 段落规则

v0.2.18将左/右缩进与行距三个原生判据接入正式CLI和MCP。学校模板建议独立运行；原程序没有提示不代表符合学校要求。

| 项目 | 实际生产条件 | 计数链 |
|---|---|---|
| 左缩进 | float32尺寸严格<−0.10000000149mm | parser290 → 主槽4e，>0报告 |
| 右缩进 | 同上，独立右属性 | parser294 → 主槽4f，>0报告 |
| 行距 | float32尺寸×float32(56.6929130554)+0.5，经006b70b8向零截断后整数<180 | parser298 → 主槽50，>0报告 |

三项都受检查启用与非空文本门限制，没有40字符下限。精确识别摘要/目录/引言标题后启用；无标题时第61个列表段落启用，空段落也计入序号，附加词标题反例不会自动启用。原始twips乘float32(0.017638888210058212)并存为float32尺寸。

−5twips不报、−6twips报，正1440twips不报；行距178/179报，180/181及240/360/480不报。原文“1.5行”不是实际相等比较。Ghidra将辅助函数写成ROUND，最终以设置x87向零舍入后FISTP的原始指令为准。

[68次同输入验收](../evidence/business-map-232/paragraph-acceptance-r1/audit.json)覆盖硕士47次、博士NKR21次，42个唯一合成输入；补齐空段落、59/60边界、1001段长输入、basedOn继承、直接覆盖及单格表格。长输入普通属性采样达到128次上限时明确标记，末尾异常计数调用及最终报告仍直接观察，不伪称采样完整。[函数地图](../evidence/business-map-232/paragraph-function-map-r1/map.json)与[首行未解项](../evidence/business-map-232/first-indent-static-r1/index.json)保留地址、常量及搜索边界。首行解析存在，但生产者未恢复，不宣称不存在。

JSON的`native_paragraph_observations`提供三计数、适用状态及最多100个命中记录的属性/XML，不返回全文；诊断的`precise_locations`准确指到正文或单元格段落。

仅限已解析的普通DOCX段落，测试到1001段，最多一个启用后的无条件样式单格表格。复杂域、公式、修订、额外故事、一般绘图、编号属性、条件表格样式、双向/框架布局、PDF及其它模式保持待验证。`profile_supported=false`不能当作通过；超范围保留待复核候选。原先47个合成诊断族差异实例含重复基线，不是真实论文准确率。真实案例、MCP及回归结果以最终冻结报告为准。检测验证不扩大修复权限，缩进/行距批量修复仍关闭。
