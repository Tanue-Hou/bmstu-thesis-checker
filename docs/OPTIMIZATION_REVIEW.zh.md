# 优化复核与后续顺序

本轮依据本地脚本重新测量 Claude 的建议，案例仅用于交叉检查，不作为学校标准或准确率分母。

## 已完成

- 精简输出：CLI `check --detail compact`、MCP 检查工具 `detail=compact`。保留全部诊断、决策字段和定位总数，仅缩短证据引用及位置示例；完整模式仍为默认，复核输入要求完整报告。
- 17份既有案例报告的同条件序列化由4,907,702降至923,849字节，减少81.18%。这是传输体积收益，不是准确率提升。
- README修正参数、10个MCP工具及许可说明，历史版本移至既有版本文档。根分析项目索引移除作废阈值正文，并保留历史备份。
- 本地按Git垃圾清单及安装包逐文件CRC核验清理32个文件，释放1,590,366,452字节。未改写Git历史，未清理有效悬空对象；安装后的工具保留。详细清理回执留在分析工作区的logs目录。
- 新增完整函数反汇编留在本地私有分析目录；公共记录只保留行为规格、少量必要指令片段和来源哈希。删除“严格clean-room”表述；独立实现不代表严格隔离的洁净室开发流程。

## 分批继续

1. **证据去重**：当前规则注册表2,497,779字节，39条规则、23个验证上下文；23个上下文均通过现行完整性校验。先给证据建立内容寻址索引，再兼容迁移读取器和冻结回执，避免直接改JSON使已有证据失效。
2. **测试分层及包名**：区分自生成样本单元测试与依赖冻结证据的回归测试，并对缺少证据明确报错。云端缺少证据不能直接等同正常clone失败。正式包迁移应兼容现有CLI入口，分独立版本验证。
3. **探针流水线**：新规则优先采用统一规格与生成、执行、验证、冻结阶段；历史脚本作为已冻结实验保留，不批量改写旧证据生产过程。
4. **公开历史审计**：已有公开反编译目录与Git历史仍需单独盘点。新材料私有化不会自动撤回历史内容；本轮没有强推或重写历史。许可仍为UNLICENSED。
5. **逆向优先级**：用17份案例的规则触发频率、已确认误报和可安全修复的范围决定顺序。原程序后台对照继续作为验证手段；独立复刻目标继续推进，未以调用原程序替代。
